Case 03 · Movies and Gujarati system

One film library, multiple content systems

Operate a large Movies catalog without claiming inherited hits, and turn Gujarati film IP into full releases, serialised parts, Shorts, and Facebook cuts.

65.5M Movies lifetime 17.77M Rakhewal tenure 163 pieces from one film 6.7× FB post volume

Context

A running catalog and a regional pipeline

The Movies channel already carried a large library and a large lifetime total. The Gujarati system held the same kind of asset problem from another angle: each film could be treated as one upload, or as a set of formats that match how audiences actually watch.

Problem

Lifetime is not tenure, and one upload limits the pipeline

Claiming a full catalog total as personal output would overstate the work. At the same time, treating every film as a single upload caps the pipeline by the number of titles. The real question became: manage inherited performance honestly, and ask what else each film can become.

Strategy

Separate history, then multiply format

Keep publishing healthy on the Movies catalog without rewriting history. On Gujarati titles, format follows audience: full film for SEO, serialised parts for daily habit, Shorts for discovery, Facebook cuts for recovery and reach.

Results

Honest catalog math and a multi-format system

Movies catalog: lifetime stated plainly; tenure not mixed with inherited hits. Rakhewal: 1 film to 163 pieces to 17.77M tracked tenure views. Facebook posting volume about 6.7× after recovery.

Takeaway

What this showed

Catalogue value is not only how many films you hold. It is whether you can separate inherited performance from current work, and how many ways those films can be packaged, released, and discovered.
